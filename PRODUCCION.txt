===============================================================
  GUÍA DE DESPLIEGUE A PRODUCCIÓN — Business Development
===============================================================

ANTES DE SUBIR A PRODUCCIÓN
-----------------------------
1. Ejecutar el script de deploy (hace build + commit + push):

     Windows:   deploy.bat
     Git Bash:  bash deploy.sh

   O manualmente:
     npm run build
     git add client/dist
     git commit -m "build: actualizar dist para producción"
     git push

2. En el servidor: git pull && reiniciar Node.js


CONFIGURACIÓN DE server/.env EN PRODUCCIÓN
--------------------------------------------
DB_DRIVER=mysql
DB_USER=<usuario_mysql>
DB_PASSWORD=<contraseña_mysql>
DB_SERVER=localhost
DB_PORT=3306
DB_NAME=<nombre_bd_en_plesk>
JWT_SECRET=<cadena-larga-aleatoria-mínimo-32-chars>
JWT_EXPIRES=8h
CLIENT_URL=https://tu-dominio.com
NODE_ENV=production

⚠️  NUNCA subas el archivo .env al repositorio.


BASE DE DATOS (phpMyAdmin)
---------------------------
- Solo crear la base de datos vacía (CREATE DATABASE).
- Las tablas se crean automáticamente al arrancar el servidor.
- Las migraciones (columnas nuevas) también son automáticas.
- No ejecutar ningún SQL manualmente.


EN EL SERVIDOR (después de git pull)
--------------------------------------
npm install --omit=dev        (solo si cambiaron dependencias)
npm start                     (arranca desde la raíz)

Verificar que todo funciona:
  GET https://tu-dominio.com/api/health
  → debe devolver: { "ok": true, "db": "mysql" }


ERRORES COMUNES
----------------
- "No se ven los cambios" → faltó correr npm run build antes del push.
  Solución: ejecutar deploy.bat / deploy.sh

- "Cannot connect to DB" → revisar .env en el servidor.

- "Pantalla en blanco" → revisar que client/dist existe y tiene index.html.
